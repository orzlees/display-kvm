# 五秒输入切换测试

先在“屏组与目标主机”中保存并生效目标主机的输入映射，再从本机正在显示的画面发起“五秒输入切换测试”。测试只使用已保存的目标，不使用未保存的草稿。

后台按显示器逐屏处理。每屏先真实读取当前输入，以这次读值作为返回点，而不是把配置中的某个端口当作原输入。读值 `0` 与未取得观测的“未知”不同，界面会保留并显示实际的 `0`。

## 五秒与恢复的含义

后台向当前屏发送一次目标输入切换，从同步切换调用返回时起计算固定五秒。目标验证读回所用的时间计入这五秒；五秒不是整个多屏测试的总时长，也不是页面负责的计时器。

保持期结束后，后台重新解析设备并读取实际输入，再判断是否需要切回。需要恢复时，写入原输入后还必须取得与原输入一致的新读回，才会报告“已恢复”。请分别查看每屏的切出结果和恢复结果；切出成功不能代替恢复确认，恢复成功也不会把未知的切出结果改成成功。

以下情况会影响执行：

- 预读失败、缺少可靠读值或缺少读取能力时，不切出。
- 实际原输入与已保存目标相同时，跳过切换，无需恢复。
- 恢复前已读到原输入时，无需再次写入。
- 恢复前读到既非原输入、也非目标输入的第三个值时，报告冲突，不覆盖该输入。
- 任一屏恢复失败、结果未知或出现冲突时，停止后续屏的测试，并保留逐屏结果。

## 页面关闭、超时与失联

关闭页面或重新加载页面不会取消后台测试与恢复。强制终止后台进程或断电会中断自动恢复，此时软件无法完成恢复，需人工处理。

页面倒计时归零、请求超时或连接断开，都不能证明显示器已经恢复。失联后页面只查询原测试会话，不会重新发起测试；请使用“查询原测试会话”查看后台证据，不要反复点击开始。结果未知时，最后收到的状态也不能充当恢复确认。

## 显示器与链路限制

普通输入提交与安全预览分别判断。预览必须先取得目标协议的新鲜、可靠读回；无法读回时不开始写入，也不盲目恢复。当前 Windows LG 特殊路径只提供提交回执，不提供该私有协议的可靠读回，因此不能执行五秒安全预览。普通明确切换可使用已配置的 LG 输入方案，但提交成功不等于已验证切屏；必要时通过显示器 OSD 手动恢复。macOS 等路径同样以实际读回能力决定预览是否可用。

显示器切到其他视频输入后，本机能否继续通过 DDC（显示器控制通道）读写，取决于显示器、连接链路和驱动。有些设备会在本机不再是当前视频输入时中断控制，因此不能保证单主机一定可以自动切回。

失去控制或无法确认恢复时，请用显示器的 OSD（屏幕菜单）手动切回本机输入。软件测试仅验证相应软件路径，不能证明实际显示器、转接器、扩展坞或驱动已通过硬件验证。
