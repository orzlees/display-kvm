# 故障排查

先保留可行动的终端错误，并删除端点令牌、个人路径、序列号等私有信息。不要公开私有运行目录的原始文件或完整外部工具输出。

| 现象 | 优先核查 |
| --- | --- |
| CLI/桌面连接失败 | 后台是否单独启动、客户端是否同一用户、端点是否为当前后台、运行目录属主和权限是否正确 |
| 外部工具不可用 | `-tool` 是否为真实可执行文件的绝对路径，平台与工具是否匹配；不会自动搜索 PATH |
| 能枚举但无法切换/读回 | 显示器 DDC/CI 能力与设置、工具返回错误、总线权限、扩展坞/转接器链路、已校准的设备与输入值 |
| 输入显示 `unknown` | 当前没有足够的读回证据；发送回执不能替代读回或实际画面确认 |
| 规则无动作 | 规则是否成功加载、实际事件能力是否可用、事件名/属性是否匹配；`accepted` 只表示接收 |
| 日程不能保存 | 后台是否传入 `-schedules`、是否使用旧后台、文件及父目录是否可写、页面是否报告运行代已变化 |
| 日程未触发 | 启用状态、目标、`HH:MM`、明确时区、后台真实下次触发，以及固定 `skip` 和恢复来源限制 |

macOS/Linux 私有运行目录应归当前用户所有，目录权限0700、私有文件0600。不要对整个配置树或系统设备执行递归放宽权限。Windows 当前的传输和私有 IPC 保护边界见[兼容表](compatibility.md)。

## 配置加载失败

先停止后台、保留备份，再检查文件。显示器配置当前版本3，可只读验证：

```sh
go run ./cmd/displaykvm config check --file /PATH/config.json
```

规则和日程是独立版本1文件，没有对应 CLI 离线校验子命令。按启动错误修复其实际内容后重新启动，不删除全部配置以掩盖错误。

## 保存结果或提交结果不明

分别核对“已落盘”和“已生效”。原子替换后发生错误时文件可能已经保存，不能据错误提示直接推断未落盘。使用页面或校准查询按原提交 ID 获取结果，不重复应用；等待取消也不会撤回已发送的物理动作。

文件无法严格重读时后台会停止相关运行能力。停止后台后保留三类文件备份并按错误修复，再重新启动；不要把旧轮次或旧界面状态当作恢复成功。

## 切错输入与兼容反馈

用显示器物理菜单恢复可见输入，核对设备绑定、校准依据和目标，不盲目重复试切换或套用输入代码。报告问题时区分枚举、发送、读回与实际画面证据，附脱敏后的最小复现步骤和[兼容记录](compatibility.md)所需信息。
