# 单一完整配置文件设计

状态：2026-11-06用户已选择“按此设计实施（推荐）”，授权以下范围连续实施及独立验证。

## 目标与需求

- U1：以一个完整配置文件保存设备、输入方案、分组、校准、事件规则、定时任务及运行工具设置，替换启动页的四条文件路径。
- U2：启动页提供新建、加载已有配置、另存为，保留服务和桌面两个独立登录启动开关。
- U3：加载只选择下次服务启动使用的文件，不启动、停止或重启当前服务；现有业务页面继续编辑已连接后台的实际配置。
- U4：完整文件模式下，各业务页通过现有后台管理事务更新对应部分，合并其它部分后原子保存同一个文件，不建立第二套编辑后端。
- U5：旧多文件格式与旧命令行行为继续兼容。需要迁移时显式导入并另存新文件，不自动覆盖或删除旧文件。
- U6：保留已验收的取消选择不跳动、草稿和焦点保持、表单版本保护、错误不自动重试及未知开关不误禁行为。
- U7：修复macOS登录状态输出兼容性，接受true/false和enabled/disabled并保持“是否禁用”的语义；真实系统状态不因查询或验证被改变。
- U8：独立完成受影响包、统一事务和原生文件操作验证，构建新的macOS候选及归档，保留旧产物和失败证据。

## 方案与取舍

采用独立的完整配置文档，内嵌现有业务配置、规则、日程与运行工具设置。保留原业务配置类型及严格管理快照协议，复用唯一后台管理循环、Prepare/Apply和运行代机制。新格式内部启动档案只记录选定完整文件的位置；旧档案读取与显式旧命令写入继续兼容，新界面使用新格式，不自动迁移旧档案。

只把四个旧路径藏进另一清单，仍要求用户维护多个文件，不能满足本次目标。直接把规则、日程类型放入现有Config会产生现有模块反向依赖问题，因此由独立文档层聚合，具体类型与文件边界由实施计划固定。

## 文件操作与运行语义

新建和另存为只有完整写入成功后才更新选定位置；取消和错误保留原位置及草稿。原文件保留。选择文件和保存登录安排分别表达，不假称已经切换当前运行服务。

正在由后台使用的完整文件禁止另一离线写入者直接覆盖；另存为可创建新文件。采用明确的文件写锁与现有原子保存能力，不把写后校验宣称为跨进程版本比较。坏格式、未知版本、路径或写入冲突显式报错，不降级为空文件覆盖。

macOS写锁使用配置父目录中的私有隐藏目录 `.displaykvm-settings-locks`，锁文件名与配置文件名保持一致，由同一文件系统处理大小写及Unicode等价。该目录只在获取写者时创建，加载不创建；普通配置父目录不被强制改为私有权限。Linux继续使用内部路径摘要锁。锁布局不对旧实现的写者宣称协调，验证不得自动停止既有服务。

外部控制工具仍是独立可执行程序，其设置记录在完整配置内；不把工具程序嵌入JSON，不新增工具依赖或偷偷搜索PATH。

修改共享完整文档读写、后台加载和事务保存、内部启动档案及CLI、启动设置页面和必要原生保存对话接线，附直接相关测试和使用说明。准确文件与接口由实施计划逐项说明。
