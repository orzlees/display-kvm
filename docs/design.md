# 显示器切换工具：产品与架构草案

状态：草案，待用户评审。当前仅有规划，没有实现或可复核的本项目硬件实测。工作名称 `displayKvm` 来自仓库目录；公开名称、许可证、Go 模块路径和最低版本均由任务 01 确认。本文的架构、首版边界和默认行为是建议，不代表用户已批准。

## 目标与原始需求

USB 切换器共享键盘、鼠标等外设，视频线仍分别连接各台主机。工具根据设备事件，通过 DDC/CI 改变显示器输入源，减少操作显示器实体按键的次数。目标平台为 Windows、macOS、Linux，提供可独立运行的命令行与美观简易的桌面端。用户偏好 Go，已明确不要 Web 界面，不满意 Fyne 默认布局和按钮；GUI 框架尚未选定。

| 编号 | 产品需求 | 当前状态 |
| --- | --- | --- |
| R1 | 三平台输入源切换 | 仅规划，无实现 |
| R2 | 可独立运行的 CLI 及简易非 Web 桌面端，重视视觉 | 仅规划，无实现 |
| R3 | 系统支持的事件可选择和筛选，支持 USB 触发、自定义事件入口与定时 | 仅规划，无实现 |
| R4 | 显示器识别、人工绑定、诊断和端口校准 | 仅规划，无实现 |
| R5 | 单屏、多屏、分组手动和自动切换，以及每屏主机到输入的映射 | 仅规划，无实现 |
| R6 | 可靠执行、部分失败可见、状态可信 | 仅规划，无实现 |

## 候选架构与首版边界

建议使用 Go 核心、CLI、单一用户会话后台进程和可替换桌面层，共用领域模型与配置契约。CLI 与桌面向后台发本地请求，由后台统一调度显示器写入，避免两个入口同时直写同一显示器。CLI 必须可独立安装，GUI 的语言、依赖及工具链不得进入 CLI 和后台的构建链。

后台未运行时是提示连接失败、按需启动还是采用其他连接策略，由 01 与 10 明确。跨语言桌面可通过本地 IPC（进程间通信）共用 Go 核心，这不意味着采用 Web UI；具体传输与协议由 01、03 确认。后台按平台选择显示器后端与厂商协议策略，事件来源通过统一接口输出规范事件及平台能力目录。统一签名、消息、错误和配置以 03 为唯一契约，后续任务不得各自定义同名接口。

首版建议每台主机独立运行，USB 取得方按规则切到自身目标配置；单机也能手动切到已接视频线的其他目标。主机目标是用户命名的视频来源和每屏端口映射，不是自动发现另一台电脑。切走后本机可能失联，必须保留这一事实。远程主机协调、网络 KVM、远控不在首版承诺中。

## 配置对象与执行状态

建议的配置对象包括：显示器逻辑身份、设备分组、主机逻辑目标、输入控制方案、事件条件、规则动作和定时项。显示器逻辑身份使用 EDID（显示设备识别数据）、路径等候选信息加人工绑定，不能假定序列号唯一；主机目标保存每屏端口映射，输入控制方案区分标准 VCP（虚拟控制面板代码）与厂商策略及校准参数。

配置版本化、校验、迁移、格式和错误处理由 03 定义。优先标准库或已有能力；配置格式、第三方库、框架和新增依赖先确认，不预定 YAML 库。

建议执行链为：事件筛选 → 防抖和去重 → 必要的重新枚举 → 形成带请求标识的动作 → 排队执行 → 每屏有限重试及结果记录。启动与唤醒补扫覆盖程序启动前已存在的 USB；取消和超时必须释放资源。多屏动作不保证原子性；切走可能丢失 DDC 通路，不能承诺自动回滚。

| 状态 | 含义与限制 |
| --- | --- |
| 请求已接受 | 已收下请求，尚不能证明命令发送 |
| 命令已发送 | 传输已发送，不等于目标主机画面可见 |
| 可读回确认 | 输入读回与目标一致，仍不证明目标有视频画面 |
| 失败 | 有明确失败依据，应说明所属屏与原因 |
| 未知 | 失联、不支持读回等导致无法确认，保留最近观测和时间 |

未来涉及并发、旧协议兼容和资源释放的实现，须使用客观中文原因注释解释约束、隐含假设与修改风险。不得把复杂失败路径简化成“发送成功即切换成功”。

## 平台事实与风险

| 平台或问题 | 规划依据与待验证边界 |
| --- | --- |
| Windows | Dxva2 的 `SetVCPFeature` 是标准控制路径；部分 LG 可能需要原始 DDC 或 GPU 专用后端。博客使用的 amdddc 仅适用 AMD，其仓库许可尚未确认，不能承诺捆绑或跨 GPU 可用。 |
| Linux | 评估 ddcutil、i2c-dev 和设备访问权限。调用外部 CLI 与链接 lib 的依赖、许可、分发影响分别评估，不混为已批准方案。 |
| macOS | Intel、Apple Silicon、SoC、端口与扩展坞组合有差异；m1ddc 当前覆盖部分 LG 的 `input-alt`，不支持 Intel。2025 年博客中 M4 失败只是历史观测，不代表所有现有机器结论。 |
| 登录与会话 | Windows Run 仅在登录后执行；建议的用户会话后台不保证登录前工作。权限和登录前需求在 01 确认。 |
| 枚举与能力 | DDC capabilities 可能不完整，显示器索引会变化；自动输入扫描、睡眠和多主机争抢都应能诊断，不能假定读回始终可用。 |
| 事件 | 公开平台能力与具体不支持原因，不能承诺一个库监听任意事件。系统未直接支持的自定义触发优先使用 CLI 入口，不先建设 Go 动态插件系统。 |

## 桌面方案比较

| 候选 | 收益 | 成本及限制 |
| --- | --- | --- |
| Go + Fyne | 同语言接入较直接 | 自绘默认风格不符合用户当前审美，定制成本需评估，不能据此锁定框架 |
| Go 后台 + 其他非 Web 跨平台 GUI | 视觉选择较多，核心仍可复用 | 跨语言接入、工具链、平台依赖与打包成本需权衡，具体候选由 02 确认 |
| 各系统原生界面 | 可优先适配平台体验 | 三套界面与生命周期维护成本高 |

三者都是候选。用户仅确认不要 Web，并未批准框架、配色、布局或默认行为。[交互与视觉草案](ui-design.md) 已形成文字草图，后续供 02 评审；本轮不会制作可执行原型。

## 计划与验证边界

[总计划](任务计划/【20261105-显示器切换工具开发】.md) 分离前置决策与未来实施。01 确认技术、依赖、许可及真实硬件边界，02 确认桌面框架及 17–21 的准确测试命令、文件后缀和构建前提，03 产出唯一领域及接口契约。仍有未知时形成决策记录并标记阻塞；不允许按推荐方案默默开工。01、02 引起接口、路径或命令变化时，先更新受影响任务并交用户评审。

普通实施代理不跑任务测试，专属独立验证代理仅运行本任务定向单元测试。三平台实际运行、集成、硬件切换、完整构建和打包验收统一留给 24，且需全部前置完成并明确选中。没有设备或环境的组合保留“未验证/受阻”；计划、模拟测试和引用博客均不能代替本项目实测支持声明。本轮不执行任何项目测试。
