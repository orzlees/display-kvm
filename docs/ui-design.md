## 主题：系统优先，未知深色

默认模式为“跟随系统”。CSS先使用深色基础色，若WebView报告系统浅色则首屏采用浅色；JavaScript通过`prefers-color-scheme`的明、暗查询及变化事件同步外观。只有一个查询明确匹配时视为可读结果，两者均不匹配、能力缺失或无法确定时用深色，并在页脚说明。系统浅色可读时显示浅色，不再等待旧T1歧义确认。

“深色 / 浅色”只覆盖本次窗口会话，页脚提示“仅本次有效”；切回系统立即重新计算。关闭再打开回到系统模式。当前不写持久化偏好，不新增核心配置。系统通知只改变CSS色值及说明，不重建页面、请求设备或重发操作。原生标题栏仍由系统负责，不能用内容区换肤推定所有系统菜单都已经适配。

系统WebView可能将平台不可读状态折叠为明确浅/深；本实现只能识别它公开给页面的查询结果，不能证明底层系统来源始终可靠。独立烟测须分别核对当前系统外观、临时明暗、切回系统和可观察到的变化；真实系统通知及未知分支证据不足时如实保留缺口，不拿静态色表当验证。

## 刷新、错误与关闭

页面初次加载及“刷新状态”只向Wails内部同源`GET /client/status`读取本客户端状态。Go返回`not_configured`、`not_read`与空数组；这些只供此窗口解释，不是03核心协议。资源由内嵌处理器提供，不开启监听端口、前端开发服务器或后台进程。

成功显示“客户端状态已更新 · 尚未读取显示器”；超时/错误显示独立提示并保留未读取状态，控制台保留真实原因。关闭窗口取消本地等待；macOS关闭最后窗口结束GUI进程，不停止后台。本次不实现隐藏到托盘，也不改变登录自启。

## 首次配置与试切

1. 发现显示器、能力和权限。
2. 确认身份：型号、可用序列、系统屏号和连接位置仅作辅助；屏号不是永久ID。存在歧义时不自动合并，暂停相关规则。
3. 命名主机，逐屏建立实际端口映射。
4. 单屏逐候选试切：目标应有视频链路，先记下原输入及实体键返回方法。
5. 分别记录发送、读回和人工确认依据。
6. 保存配置后再由用户启用规则，建议默认关闭；该默认尚待确认。

试切可能使本机失去画面和DDC通路，不能承诺倒计时恢复。兜底方式是通过显示器实体键或摇杆选回原输入；软件仅在原输入已知且通路可用时尝试回切。首次逐屏校准，避免同时切走全部操作界面；日常操作不重复相同风险弹窗。

## 状态与反馈

| 状态 | 呈现与可执行动作 |
| --- | --- |
| 可用 / 待绑定 | 明确当前可执行项；待绑定先确认身份，不把歧义设备直接当可切换 |
| 等待 / 执行中 | 说明正在排队还是操作具体屏，并给出终点/结束结果 |
| 已发送 | 仅表示命令发送，不称画面成功 |
| 已读回确认 | 输入与目标一致，但不证明目标主机有画面 |
| 结果未知 / 无法确认 | 解释失联或不支持读回，保留最近观测时间 |
| 离线 / 权限不足 | 保留映射，提供重新检测或权限指引 |
| 能力不支持 | 区分不能切换与不能读回，禁用对应操作项 |
| 部分失败 / 部分未确认 | 按屏及数量呈现；未确认不等于明确失败 |
| 跳过 / 已取消 | 显示原因；取消仅阻止尚未发送动作 |

多屏不是原子事务，不保证回滚。“仅重试失败屏”须明确范围，避免已确认屏重复动作。规则建议人工操作优先、同屏串行、抑制重复事件并记录原因；时间阈值交核心验证。定时错过建议跳过并记录，这些默认和策略均待决策确认。

### 主题解释 T1：跟随系统、深色兜底（待确认）

用户明确要求“根据系统切换皮肤，默认黑色”。这里有一个尚未消除的歧义：若系统当前为浅色，“首次立即跟随系统”会显示浅色，而“首次一定黑色，之后手动开启跟随”会显示深色。以下T1采用前一种解释，不能当作用户已批准；若用户指后一种，只将首次默认模式改为“深色”，手动选择“跟随系统”后仍按相同规则工作。

T1候选默认模式为“跟随系统”；深色是尚未取得可靠系统结果或明确不可读时的皮肤，而不是把已读到的浅色覆盖成黑色。深色采用接近黑色的中性炭黑基底`#111314`，不是此前偏蓝背景；本色值也是视觉候选，未把“默认黑色”擅自解释为必须纯`#000000`。

## 关键任务的具体交互

### 选择与执行

1. 配置选项只改变“待应用”状态，立即展示每块已选屏的目标端口；按“应用到N块屏”才请求后台。单屏行内切换也先显示该屏目标，不隐含套用其他屏。
2. 缺映射/待绑定/离线项保留在选择范围并显示原因。不能执行时，应用区显示“2块中1块缺映射 → 去配置”；是否允许显式选择可执行子集由03/核心契约决定，GUI不能无声剔除。
3. 请求中保留范围和目标快照，按钮显示“正在请求”；接到后台结果后按屏更新。等待/执行中/已发送/已读回确认/结果未知/明确失败保持独立。
4. “取消后续操作”只阻止未发送项；“仅重试失败屏”按核心结果给出屏名与数量，不能把未知屏或已确认屏自动纳入。读回重试与重新发送切换命令使用不同文案。
5. 连接中断时保留最后观测并标“观测于10:42，连接已中断”；禁用新的切换提交，提供“重新连接”和后台手动启动说明。不会自动启动后台、访问DDC或在本地假定执行成功。

### 键盘、焦点与辅助技术

正文对比度目标4.5:1，大号文字、边界和必要图形目标3:1；上述明暗色值是设计候选，尚未测量。所有状态有文字；禁用动作旁有可聚焦的说明，不仅依赖颜色或悬停提示。焦点环2宽、与控件间隔2，使用T1对应布局与皮肤的焦点色；不能被圆角裁掉。

Tab顺序为页面导航→范围→配置选择→应用→设备行→结果/详情；选择组内方向键移动、空格选择，Enter仅激活当前焦点动作，不设全局Enter切屏。Escape关闭菜单/详情，不自动取消已发送请求；表单未保存时先询问放弃或继续编辑。应用结果通过状态文本和辅助技术通知，消息到达不抢焦点。中文输入法组合期间Enter不能触发保存或切换。辅助技术角色/名称/选中/禁用状态沿用标准控件语义，自定义外观必须保留这些能力。

动画仅建议页面首次呈现140毫秒轻淡入、位移不超过4；按钮颜色变化100毫秒；持续执行只使用带文字的进度指示。系统减少动态效果时关闭这些过渡。不做背景闪烁、逐行状态跳动或为每条日志重复入场动画。以上为后续实现目标，不是当前能力证明。

## 托盘、窗口和后台候选行为 B1

以下行为需要随本批准包明确确认，当前待批准：关闭窗口退出GUI进程，Go后台保持原有运行状态；“隐藏到托盘”是单独菜单动作，只有确认托盘可用时才提供。菜单固定包含“打开窗口”、已校准常用配置（须明确范围）、“查看最近结果”和“退出界面”。暂停规则仅在核心提供明确能力时出现，不在GUI本地伪造暂停。

托盘请求与窗口共用同一客户端和执行状态；切换结果不能只弹一条“成功”。Linux托盘不可用时禁用隐藏动作，并在窗口说明“当前桌面无可用托盘，请保留窗口或通过启动器重新打开”；不以支持某个库API代替真实托盘可用性判断。退出界面不冒充停止后台；后台手动启动/停止和登录自启是否提供由相关核心与平台任务另定，本包不授权改变自启默认。

## 框架评估的五项证据标准

1. 三平台非Web实际运行与分发、Go核心复用及工具链要求。
2. 同一关键视图的视觉实现和自定义绘制成本。
3. 中文、键盘焦点、辅助技术和缩放。
