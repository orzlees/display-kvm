## 登录启动功能候选

新增的macOS登录启动功能使用当前用户的两个独立登录任务，分别启动服务和桌面；设置方法与生效边界见[使用说明](usage/README.md#macos登录启动与桌面驻留)。本节记录实现范围与待执行检查，最终测试、构建、包装和GUI结果应由独立验收补充，当前不标记通过。

候选构建使用独占目录，不覆盖 `desktop/bin/DisplayKvm.app` 或任何旧运行目录。在项目根目录执行：

```sh
project_root=$(pwd -P)
./desktop/build-macos.sh --output "$project_root/build/out/loginstart-20261106/DisplayKvm.app"
./packaging/package.sh desktop --run-id loginstart-20261106-package --app "$project_root/build/out/loginstart-20261106/DisplayKvm.app"
```

`project_root` 取当前项目的真实绝对路径；这些命令尚未在本功能实施阶段执行。构建目录及应用目标已存在时拒绝接管，失败现场保留；包装使用不同的新编号。无参构建仍选择原桌面输出路径，但同样拒绝覆盖已有应用。候选目录的身份标记与包装目录区分，包装仅接受原桌面路径或项目 `build/out/单个构建编号/DisplayKvm.app` 的受控布局，不接受符号链接或任意外部应用。

应用内三个程序分别从真实入口构建：`displaykvm` 为桌面模块的GUI主入口，`displaykvmd` 与 `displaykvm-cli` 分别为根模块后台和CLI。沿用Go1.27.3、本机离线缓存、只读模块及最低macOS13；桌面保留 `production` 构建标签，后台保留CGO原生事件支持。辅助程序先做本地ad-hoc签名，再签整个应用并严格验证；这不等于正式签名或公证。

桌面包装按三个程序各自实际的 Go BuildInfo（构建信息）核对入口、模块、目标和构建参数，再收集实际链接模块及Go工具链许可，分别列入 `manifest.json` 和 `SHA256SUMS`。未链接的模块声明不能冒充依赖载荷；普通非空许可文件、来源归属、哈希和复制一致性检查继续保留。新包装明确拒绝缺少后台或CLI的旧单程序应用，旧工件与历史证据保持原样，核心六目标包装及 `archives.json` 语义不变。应用包不携带用户业务配置、实际控制工具或私有源目录。

待独立验收：定向测试、一次新候选构建与包装、三个程序的Mach-O/构建信息/签名/许可核对，以及可安全完成的桌面观察。真实注销、重启、登录、权限拦截和硬件操作仍需单独记录人工证据；不能用设置文件生成或托盘对象创建替代。
